# 性能优化：响应卡顿与大文档假死

## Context（为什么做这件事）

编辑器存在四类性能瓶颈，导致响应卡顿与大文档假死：

- **瓶颈 A（状态栏）**：`views/status_bar.py:46-55` 在每次渲染都全文 `parser.serialize(document)` + 正则词数扫描 + 遍历行计段数。由于 StatusBar 直接读 `document.lines`/`line.raw`，它**每按键就独立重渲染**（不只是等 App 重渲染），且整棵 Text 树重建。光标行列本应实时更新，却只在 App 重渲染时才刷新。
- **瓶颈 B（侧边栏）**：`views/sidebar.py` 4 处 `ft.Column(scroll=AUTO)`（L401/513/605/692）无虚拟化；`_scan_markdown_files`（L426）同步递归 `os.scandir` 每次 Sidebar 渲染都跑（含过滤框每次按键）；`_compute_toc`/`_match_lines`/`_filter_tree` 每次渲染 O(n) 且无 memo；动态列表项全无 `key`。Sidebar 也直接订阅 document，每按键重渲染。
- **瓶颈 C（编辑器长文档）**：`views/editor/__init__.py:596-605` 用 `ft.Column(scroll=AUTO)` 一次性构建所有 LineView，数千行假死。`_scroll.py` 的两步滚动逻辑本就是为 ListView 懒构建设计的，但渲染却用 Column，二者不一致。
- **瓶颈 D（diff 对比）**：`app/_render.py:289-293` 每次渲染都 `serialize(left)+serialize(right)+compute_diff`。diff 模式下 serialize 读取所有 `line.raw`，导致 **App 每按键重渲染**。

预期结果：光标/字数实时更新只走状态栏局部 `update()`；侧边栏长列表虚拟化 + 数据 memoize；编辑器大文档视口外行不构建；diff 模式 App 不每按键重渲染。

## 架构决策（已与用户确认）

1. **编辑器切 ListView**（非保留 Column+渲染窗口）。`build_controls_on_demand=True` + `cache_extent=600`，禁用 `item_extent`/`first_item_prototype`（LineView 变高）。已验证 `max_scroll_extent` 估算化对滚动/diff 同步零影响（无消费者读 `max_scroll_ref`；`DiffScrollSync` 只用 offset）。
2. **diff 做 memoize + 组件拆分**：新增 `DiffMarkers` 组件封装 serialize+compute_diff，让 App 不再订阅 `line.raw`，从根本上消除 diff 模式每按键 App 重渲染。
3. **高频 UI 命令式更新**：状态栏光标/字数改用 `ref` 持有 Text 控件 + 控件级 `.update()`，跳过 `set_state`。符合用户规则 2。

## 实施步骤

### 阶段 1：状态栏命令式解耦（瓶颈 A）— 规则 1+2+4

**核心思路**：光标位置经编辑器 `use_effect` 上报 → App 路由 → 命令式改 StatusBar 的 Text.value + `.update()`；字数经 `mark_dirty` 触发 300ms 防抖异步任务 → 序列化+计数 → 命令式更新。StatusBar 首次渲染/切标签/切主题仍从 document 算初值保证正确性。

**改动点**：

- `views/status_bar.py`：
  - 签名移除 `cursor_row_col`，新增 `status_ref: ft.Ref`（App 注入）。
  - 对 5 个高频 Text（cursor/word/char/para/reading）各加 `ft.use_ref`，Text 上挂 `ref=xxx_ref`。
  - `ft.use_effect(_register_updaters, [theme_mode])`：把 `update_cursor(row,col)` / `update_counts(word,char,para,reading)` 注册进 `status_ref.current`（直接改 `xxx_ref.current.value` + `await xxx_ref.current.update()`）。`[theme_mode]` 依赖确保主题切换重建 Text 后重新注册（Plan agent 指出的关键风险）。
  - 渲染期仍从 document 算初值赋给 Text.value（覆盖首屏/切标签/主题切换）。
- `views/editor/__init__.py`：
  - 新增 props `on_cursor_move: Callable[[int,int],None]|None`、`on_content_change: Callable[[],None]|None`，透传进 EditorContext。
  - 新增 `ft.use_effect(_report_cursor, [cursor_li, cursor_off, cursor_line, nav_seq])`：复用 `_scroll.py:376-379` 的 `get_cursor_row_col` 同款逻辑（`cursor_li is not None → (li+1, off+1)` 否则 `(cursor_line+1, 1)`）调 `on_cursor_move`。**关键**：用 use_effect 而非 instrument `_set_cursor`，可覆盖围栏块/undo/IME 结束等 15+ 散点路径（Plan agent 纠正）。
  - `mark_dirty`（L175-180）内、守卫之后调 `on_content_change()`（在 `reparse_line_atomic` 之后，document 状态已更新）。
- `views/editor/_context.py`：EditorContext 加字段 `on_cursor_move`/`on_content_change`（Props 区，默认 None）。
- `app/_context.py`：AppContext 加字段 `status_ref: ft.Ref`（Refs 区）。
- `app/__init__.py`：
  - 新增 `status_ref = ft.use_ref(None)`，写入 ctx。
  - 装配 `on_cursor_move`/`on_content_change` 回调（在 `_editor_common` 构造前定义，供 `_render.py` 用）：
    - `on_cursor_move`：None 守卫 + **多编辑器来源路由**（拆分/对比模式下只接受焦点视口的上报，比对 `get_active_nav()` 与来源 nav_ref；给 MarkdownEditor 传一个稳定 `source_nav_ref` 标识，或用 `on_editor_focus` 已有的 active_pane 机制过滤）。
    - `on_content_change`：防抖 300ms 异步任务。调度时捕获 `sched_idx=active_index_ref.current` 与 `sched_doc=tabs_ref.current[sched_idx]["document"]`；执行时校验 `sched_doc is tabs_ref.current[sched_idx].get("document")` 防跨标签竞态；diff 模式按 `diff_active_pane` 选焦点侧 doc；算完调 `status_ref.current.update_counts(...)`（None 守卫）。防抖计时器用 `use_ref` 持有，新调用取消旧的。
- `app/_render.py`：移除 L167-169 `cursor_row_col` 读取与传参；StatusBar 调用（L171-183）改新签名（`status_ref=ctx.status_ref`，去掉 `cursor_row_col`）；`_editor_common` 加 `on_cursor_move`/`on_content_change`。

### 阶段 2：侧边栏 memoize（瓶颈 B 部分）— 规则 1+4

**改动点**（`views/sidebar.py`）：

- `_compute_toc`（L746）包 `ft.use_memo`，依赖签名 `tuple((i, l.level, l.raw) for i,l in enumerate(document.lines) if l.block_type==BlockType.HEADING)`。复用 `editor/__init__.py:451-455` 的 `_toc_sig` 模式（用 `l.raw` 字符串本身，**非** `id(l.raw)`）。
- `_match_lines`（L747）包 `use_memo`，依赖 `(tuple((i, l.raw) for i,l in enumerate(document.lines)), search_query)`。
- `_scan_markdown_files`（L426）包 `use_memo`，依赖 `(workspace_folder, file_path)`（非计算后的 root_dir，避免重复 isdir）。
- `_filter_tree`（L427）包 `use_memo([full_tree, file_filter])`；`_flatten_tree`（L428）包 `use_memo([filtered, root_dir])`。
- **所有 use_memo 依赖加 `theme_mode`**（Plan agent 指出：否则主题切换时 Sidebar memo hit 不重渲染取色，颜色不更新）。
- 提取 `tabs`（L790-802）、`drag_handle`（L760-769）为 `use_memo` 复用静态控件。

### 阶段 3：侧边栏 ListView + 异步扫描（瓶颈 B 剩余）— 规则 2+3+4

**改动点**（`views/sidebar.py`）：

- 4 处 `ft.Column(controls=items, spacing=0, scroll=AUTO)` → `ft.ListView(controls=items, spacing=0, build_controls_on_demand=True, expand=True, on_scroll=...)`：
  - L401-419 最近文件：`key=f"recent-{p}"`，`first_item_prototype=True`（单行等高，但确保首项非头部）。
  - L513-516 文件树：`key=f"file-{abspath}"`/`key=f"dir-{abspath}"`，`first_item_prototype=True`；**工作区头部（L519-552）移到 ListView 外层 Column**，避免首项是头部导致拉伸。
  - L605-608 大纲：`key=f"outline-{li}"`，`first_item_prototype=True`。
  - L692-695 搜索结果：`key=f"search-{li}"`，**不用** `first_item_prototype`（max_lines=2 变高，Plan agent 纠正）。
- `_scan_markdown_files` 改异步：新增 `scan_state, set_scan_state = ft.use_state(("idle", None))`。首次某 root_dir 扫描用 `page.run_task` 后台执行，扫描中显示 `_empty_hint("加载中…", c)`；加 `scan_token_ref`，每次启动新扫描递增 token，完成时校验 token + `sched_root == 当前 root_dir` 一致才 `set_state(("done", tree))`（防卸载/切面板竞态）。memo 缓存命中时直接用，不异步。

### 阶段 4：编辑器切 ListView（瓶颈 C）— 规则 3

**改动点**：

- `views/editor/__init__.py:591-614`：`ft.Column(ref=list_view_ref, controls=line_controls, scroll=AUTO, on_scroll=...)` → `ft.ListView(ref=list_view_ref, controls=line_controls, build_controls_on_demand=True, cache_extent=600, spacing=0, expand=True, on_scroll=scroll_cbs["on_scroll"], padding=ft.Padding.symmetric(horizontal=content_padding, vertical=content_padding_top))`。
  - 外层 Container（L594-613）的 `padding` 改为 0（padding 迁移到 ListView，否则滚动时内容贴边被裁）。
  - `ref=list_view_ref`、`on_scroll` 从 Column 迁到 ListView（`scroll_to` 方法二者都有，`_scroll.py` 零改动）。
  - **禁用** `item_extent`/`first_item_prototype`（LineView 含段落软换行/代码块/表格/HR/MATH，高度差异大）。
- `views/editor/_focus.py:26-29` `_focus_cursor_field`：加延迟重试。`cursor_field_ref.current is None` 或 `focus()` 失败时，`page.run_task` 调度 50ms 后重试，最多 3 次（用闭包计数器）。解决光标移到视口外未构建行时 TextField 未挂载导致聚焦失败（Plan agent 指出的最关键回归）。
- `views/editor/_scroll.py` `_safe_scroll_to`（L198-255）：两步滚动的第二步（`await asyncio.sleep(0.15)` 后）末尾追加触发一次 `ctx.focus_cursor_field()`（通过 `page.run_task`），补偿 ListView 懒构建后 TextField 才挂载的时序。
- `views/editor/_render.py:88-112`：TableView 加 `on_size_change=lambda e, idx=table_start: stable_cbs["on_line_size_change"](idx, e.height)`，让表格行实测高度入 `line_heights_ref` 缓存（当前只有 LineView 上报，表格行用估算，切 ListView 后偏差放大）。
- 体验降级说明：SelectionArea 原生跨屏文本选择降级（只能选中视口内已构建行）；跨行拖拽选区走独立的 `outward_sel`+`highlight_map`+`LineLayoutCache`（`_scroll.py:286-320`，不依赖控件构建），不受影响。

### 阶段 5：diff memoize + 组件拆分（瓶颈 D）— 规则 1+4

**Phase 5a：memoize（先做，零风险）**
- `app/_render.py:_build_diff_area` 的 `serialize+compute_diff` 提到 App 顶层 `ft.use_memo`（hook 顺序约束：必须在组件函数体顶层无条件调用，非 diff 标签用占位依赖返回 None）。依赖行签名 tuple：`(tuple((i,l.raw) for i,l in enumerate(_ldoc.lines)), tuple((i,l.raw) for i,l in enumerate(_rdoc.lines)))`（**非** `id(doc)`——`id` 永不变，memo 永不失效，Plan agent 纠正）。

**Phase 5b：组件拆分（根本解决）**
- 新增 `views/diff_markers.py`：`@ft.component def DiffMarkers(left_doc, right_doc, on_update)`。内部 `ft.use_state` 持 marks/gaps，`ft.use_effect` 订阅双文档行签名 → serialize+compute_diff → `set_state` + 调 `on_update`。这样 **App 不再调 serialize，不再订阅 line.raw**，diff 模式 App 不每按键重渲染。
- `app/_render.py:_build_diff_area`：移除 serialize/compute_diff；渲染 `DiffMarkers` 组件 + 两个 MarkdownEditor；marks/gaps 经 `ft.use_ref` + `on_update` 回调写入，MarkdownEditor 从 ref 读初值（声明式），DiffMarkers 更新后命令式触发编辑器局部 `update()`（或经 ref 写入后 set_state 触发编辑器重渲染——但编辑器是 diff 标签下独立实例，重渲染成本可接受）。
- `app/__init__.py`：移除 Phase 5a 的 use_memo（被组件拆分取代）。

## 验证

1. **启动**：`python main.py`（或 `ft.run`）。确认编辑器、侧边栏、状态栏正常显示。
2. **状态栏实时性**：移动光标（方向键/点击/跨行），状态栏"行 X 列 Y"实时跟随且无整页闪烁；连续打字时词数/字符数 300ms 后更新（防抖），打字过程不卡。
3. **大文档假死**：粘贴/打开 3000+ 行文档，滚动流畅；光标移到视口外行能正确聚焦（验证延迟重试）；大纲跳转贴顶。
4. **侧边栏**：文件树/大纲/搜索滚动流畅（虚拟化）；过滤框快速输入不卡（memo 命中，不重扫）；切换工作区显示"加载中…"。
5. **diff 对比**：开对比标签，两侧编辑，diff 标记实时更新；App 不每按键重渲染（观察状态栏/侧边栏不闪烁）；两侧滚动同步正常。
6. **主题切换**：亮↔暗切换，状态栏/侧边栏颜色正确刷新（验证 `[theme_mode]` 依赖）。
7. **拆分编辑器**：Ctrl+\ 拆分，左右移动光标，状态栏只显示焦点侧（验证多编辑器路由）。
8. **IME**：中文输入法组合输入不卡顿、不丢字（验证 on_content_change 防抖不影响 IME）。
9. **既有测试**：`pytest tests/`（test_autosave/test_cursor 等）全绿。
10. **回归重点**：光标移到视口外行聚焦、跨行拖拽选区、表格滚动定位、diff 同步滚动、撤销/重做后状态栏光标位置。
