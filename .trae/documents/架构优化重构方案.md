# cs-markdown-editor 架构优化重构方案

## Context（为什么做）

项目是 Flet 0.86.2 + Python 3.12 + mistune 的 Typora 式段级 WYSIWYG Markdown 编辑器，已过一轮重构（`state/`→`core/`、`utils/` 提取、`EditorActions` dataclass），分层清晰。但仍存在两类硬债务：

1. **两个超级闭包**：`main.py` 的 `App`（L65-1615，~70 个嵌套函数，横跨标签/文件/diff/自动保存/设置/键盘 7 大职责）、`views/editor.py` 的 `MarkdownEditor`（L182-3400+，~100 个嵌套函数，横跨撤销/光标/IME/导航/块/表格/选区/滚动 10 大职责）。单文件 137KB，维护风险极高。
2. **`parser.py` 单文件 40KB/873 行**，5 大职责（行内/块级/重解析/序列化/选区）混排。
3. 附带：`_file_name` 在 main.py:42、editor.py:139 重复（utils 已有）；Python 3.12 新特性（`type`/`match`/`slots`）基本未用。

**目标**：在保持功能完全不变的前提下，按职责拆分模块、应用 Python 3.12 现代语法、提升四方向性能（输入响应/滚动流畅度/启动速度/大文件编辑），让代码简洁、模块化、低耦合、易扩展、易维护。

**用户确认的策略**：渐进式（非激进重写）、parser 转包结构、四方向性能全要。

## 总体原则

- **每阶段独立可提交、可回滚**，前一阶段是后一阶段的安全网。
- **不破坏已有性能优化**：`precomputed_vlayout` 共享测量、`_offset_prefix_ref` 前缀和缓存、`reparse_line_atomic` 原子重解析、`_make_stable_cb`/`_cb_ref`/`use_memo([])` 稳定回调、`use_effect` 依赖移除 `cursor_off`、`LineEditSnapshot` 行级撤销——新优化只做加法。
- **公共接口兼容优先**：`import parser; parser.parse_markdown()` 等既有引用每阶段结束时必须可用。
- **遵守 Flet 0.86.2 坑点约束**：无 `page.open()`（SnackBar 用 overlay）、`TextButton`/`ElevatedButton` 无 `text=` 关键字、`ft.Markdown selectable=False`、TextField key 含 `li`+`nav_seq` 保 IME、`TableView` `content_width=inf`→`None`、空单元格用 `\u00A0`、`letter_spacing=0.25` 补偿不可破坏。

## 阶段划分（5 阶段，风险递增）

### 阶段 1：测试地基 + 基准建立（风险：极低）

**目标**：为后续所有改动建立可回归的安全网。当前 `tests/` 仅 3 个 smoke 文件，无 parser 选区/往返/重解析覆盖，`pyproject.toml` 未配 pytest。

**改动**：
- 新建 `tests/test_parser_roundtrip.py`：`parse_markdown → serialize` 往返一致性（标题/列表/任务/引用/代码块/数学块/表格/HR/TOC/嵌套包裹 `***a***`/行内公式）。
- 新建 `tests/test_reparse.py`：`reparse_line` 与 `reparse_line_atomic` 等价性；`staging_reparse` 不改原 line.segments。
- 新建 `tests/test_selection_ops.py`：选区四函数的单行/多行/跨行部分选中/全选。
- 新建 `tests/test_serialize.py`：`SAMPLE_MD` 黄金快照往返。
- `pyproject.toml` 增 `[tool.pytest.ini_options]`（`pythonpath=["."]`、`testpaths=["tests"]`）。
- 记录基准：启动时间、1000/5000/10000 行文档输入延迟与滚动 FPS。

**验证**：`pytest` 全绿；基准数据落地。

### 阶段 2：`parser.py` → `parser/` 包 + 启动延迟（风险：低）

**目标**：拆 40KB 单文件为按职责分层的包；mistune 实例惰性构造缩短冷启动。

**改动**：删除顶层 `parser.py`，新建 `parser/` 包（结构见下节「parser 包设计」）。`__init__.py` 重新导出全部 30 个对外符号，保持 `import parser; parser.parse_markdown()` / `from parser import serialize` 完全兼容（已扫描调用方：main.py / editor.py / status_bar.py / _typing_test.py / 测试）。

`parser/_engine.py` 用 `functools.lru_cache(maxsize=1)` 包装 `_md`/`_html_md` 构造——`to_html` 仅导出时用，启动期不再加载 `footnotes`/`task_lists` 插件链。

**验证**：阶段 1 测试全绿；`python -c "import parser; print(parser.parse_markdown('# a').lines[0].block_type)"` 正常；启动时间较基准下降。

### 阶段 3：纯函数提取 + `_file_name` 统一 + Python 3.12 现代化（风险：低-中）

**目标**：从两个超级闭包剥离「不依赖闭包状态的纯计算」与遗留重复，务实落地 Python 3.12 特性。不改变组件结构、不移动状态归属。

**改动**：
- **`_file_name` 统一**：删除 `main.py:42` 与 `editor.py:139` 本地副本，改 `from utils.file_helpers import file_name`。
- **从 `editor.py` 闭包提取纯函数到 `views/_editor_helpers.py`**（新文件）：`_estimate_line_height`、`_vline_off_at_x`、`_get_cursor_row_col` 的纯计算部分、`_table_cells` 不读 ref 部分。判定标准：函数体内不出现 `cursor_li`/`cursor_off`/`document`/`*_ref.current`/`set_*`。
- **从 `main.py` 闭包提取**：`_show_snack`/`_copy_path` 等 IO 委托提到 `services/file_ops.py`。
- **Python 3.12 现代化**（见下节清单）：`@dataclass(slots=True)` 加到 frozen 快照类与纯 layout 类；`from typing import Callable` → `collections.abc.Callable`；`type` 语句替换类型别名；高密度分发点用 `match`。
- 跑 `ruff check --fix`（`pyproject.toml` 已配 `target-version="py312"` + `select=["UP"]`）自动机械升级。

**验证**：阶段 1 测试 + 新增 `test_editor_helpers.py`；`ruff check` 无新告警；手动冒烟（输入/撤销/块切换/表格）。

### 阶段 4：子组件提取（风险：中）

**目标**：把闭包内「自成一块的 UI 构建」提取为独立 `@ft.component`，缩小每次重渲染的 diff 范围（输入响应优化）。状态归属不变，全部通过 props 下传。

**改动**：
- `editor.py` → 拆出：
  - `_raw_editor` → `views/raw_editor.py`（`@ft.component RawEditor`，props: `raw_draft`/`set_raw_draft`/`on_key_down`/`settings`/`theme_mode`）。
  - `_tool_area` → `views/tool_area.py`（`ToolArea`，props: 稳定化的工具按钮回调集合）。
  - `_build_toc` → `views/toc_panel.py`（`TocPanel`，props: `toc_entries` + `on_jump`）。
- `main.py` → 设置弹层三页构建并入 `views/settings_dialog.py`；标签右键菜单并入 `views/tab_bar.py`；diff 协调视图函数并入 `views/diff_view.py`。
- **保持 `ft.memo` 边界**：`LineView`/`TableView` memoize 不动，`theme_mode` 仍作缓存失效 prop；下传的 props 必须用 `_make_stable_cb`/`use_memo` 包装避免子组件每次重建。

**验证**：阶段 1 测试 + 手动冒烟清单；重点验证 IME 不被打断（cursor_text_field key 仍含 li+nav_seq）、`SelectionArea` 包 `Column(scroll=AUTO)` 手势不破、Flet props 坑（text= 关键字/content_width=inf/`\u00A0`）原样搬运。

### 阶段 5：控制器封装（核心）+ 可选增强（风险：高）

**5a 核心目标**：把闭包内「成组的、有状态的操作」封装为 controller dataclass，实例用 `use_ref` 持有跨渲染稳定，其方法通过已有 `_cb_ref`/`_stable_cbs` 暴露给 `EditorActions`。不改运行时行为。

**控制器划分**（详见下节「闭包瘦身策略」）：
- `HistoryController`：撤销重做 9 个方法。
- `SelectionController`：选区 18 个方法。
- `ScrollController`：滚动视口 11 个方法。
- `IMEInputController`：字符输入 7 个方法。
- `NavigationController`：光标导航 16 个方法。

**状态共享**：refs 是稳定共享层（控制器构造时接收 `cursor_ref`/`outward_sel_ref`/`history_ref`/`input_session_ref`/`layout_cache_ref`/`_offset_prefix_ref` 等），方法内读 `.current` 拿最新值（沿用 `_make_stable_cb` 已验证模式）；`set_*` 函数作构造参数下传；`EditorActions` 仍由 editor.py 渲染期从控制器方法装配，因控制器实例稳定→方法引用稳定→`KeyDispatcher` 不重绑。`EditorActions` dataclass 不扩展，控制器是内部实现不暴露给 main.py。

**5b 可选增强**（高风险，单独评估，可跳过）：
- **视口虚拟化**：`ListView` 只构建视口内 ±N 行，视口外用占位 `Container(height=...)` 撑高。风险：需精确保持滚动高度与 `hit_test` 一致性。
- **增量解析**：`parse_markdown(text, base_doc, changed_range)` 仅重解析变更区间。风险：代码块/数学块围栏闭合边界极易出错，破坏时回退全量。

**验证**：阶段 1 测试 + 1000/5000/10000 行性能基准对比；控制器方法逐个对照旧闭包行为；IME 连续输入 10 字符光标不跳；`EditorActions` 方法引用跨渲染 `id()` 不变。

## parser 包设计

```
parser/
├── __init__.py     # 重新导出全部 30 个对外符号 + __all__
├── _engine.py      # mistune 实例（lru_cache 惰性）+ 正则常量 + _INLINE_WRAPPERS 表
├── inline.py       # 行内解析：parse_inline + _split_inline_math/_flatten_text/_node_raw_text/_collect_marks/_token_to_segments
├── block.py        # 块级解析：parse_markdown + _detect_block/_make_prefix_segment/_build_line/_split_code_block/_is_table_row
├── reparse.py      # 行重解析：reparse_line/reparse_line_atomic/segment_raw/staging_reparse/line_to_raw
├── serialize.py    # 序列化：serialize/to_html
└── selection.py    # 选区操作：compute_markdown_from_selections/match_text_to_selections/compute_markdown_from_text/apply_inline_format_to_selections/delete_selections + _wrap_partial/_iter_seg_offsets/_line_display_len
```

**依赖方向（包内单向 DAG）**：`_engine`（叶子）← `inline` ← `block` ← `reparse` ← `selection`；`serialize` 仅依赖 `_engine` 的 `_html_md`；`__init__` 是唯一导入全部子模块的入口。无循环。

## 两个超级闭包的渐进瘦身策略

### 1. 纯函数提取（阶段 3，安全）
函数体内不读闭包变量、只通过参数进出的函数移到模块级。如 `_estimate_line_height`/`_vline_off_at_x`/`_heading_prefix`/`_snap_indent_up`/`_shift_cursor_off`/`_table_cells`（纯部分）。

### 2. 子组件提取（阶段 4，中等风险）
自成一块的 UI 构建函数变 `@ft.component`，props 下传。如 `_raw_editor`/`_tool_area`/`_build_toc`。props 必须稳定化（`_make_stable_cb`/`use_memo`）否则失去 memo 收益。

### 3. 控制器封装（阶段 5a，高风险但收益最大）

| 控制器 | 持有状态（refs） | 方法（成组闭包） |
|--------|----------------|----------------|
| `HistoryController` | `history_ref`/`restoring`/`undo_push_pending`/`cursor_ref`/`document` | `make_snapshot`/`push_history`/`push_line_edit`/`current_for_undo_redo`/`restore_snapshot`/`undo`/`redo`/`maybe_push_history`/`end_input_session` |
| `SelectionController` | `outward_sel_ref`/`shift_pressed_ref`/`ctrl_pressed_ref`/`selection_text_ref`/`document`/`cursor_ref` | `_set_outward_sel`/`_start_outward_from_point`/`_extend_outward*`/`_select_word_at`/`handle_outward_delete/cut/copy`/`select_all`/`handle_delete_selection`/`handle_cut`/`cut_current_line`/`_delete_raw_range` |
| `ScrollController` | `list_view_ref`/`scroll_offset_ref`/`viewport_h_ref`/`max_scroll_ref`/`_offset_prefix_ref`/`layout_cache_ref`/`line_heights_ref` | `on_scroll`/`get_scroll_state`/`scroll_to_offset`/`_safe_scroll_to`/`_ensure_visible`/`_hit_test_xy`/`_scroll_by_page`/`jump_to`/`on_content_resize`/`on_line_size_change` |
| `IMEInputController` | `input_session_ref`/`clear_value_seq`/`cursor_ref`/`document` | `handle_char_input`/`handle_paste`/`backspace_core`/`delete_core`/`on_submit`/`handle_outward_type_char`/`_end_input_session` |
| `NavigationController` | `cursor_ref`/`preferred_col_ref`/`document` | `move_*`/`page_*`/`_step_*`/`vline`/`_set_cursor`/`_cursor_base`/`_on_tap_line` |

**关键风险**：控制器方法若漏抓闭包变量（用 `cursor_li` state 而非 `cursor_ref.current`）会读到渲染期快照导致行为漂移——必须统一用 ref 读取实时光标位置（`core/cursor.py` 的设计意图）。

## Python 3.12 现代化清单

| 特性 | 应用位置 | 注意 |
|------|---------|------|
| `@dataclass(slots=True)` | `core/history.py` 的 `EditorSnapshot`/`LineEditSnapshot`（已 frozen）、`views/pixel_layout.py` 的 `LineLayout`/`VisualLine`、`services/shortcuts.py` 的 `ShortcutDef` | `@ft.observable` 的 models 类暂不动（需验证 Observable 是否依赖 `__dict__`） |
| `type` 语句 | `core/history.py` 的 `Snapshot` 别名、`utils/segment_helpers.py` 类型别名 | 3.12 原生类型别名语法 |
| `match` 语句 | `parser/_engine.py` 的 `_detect_block`（7 分支）、`parser/inline.py` 的 `_token_to_segments`（10 分支）、`parser/reparse.py` 的 `reparse_line_atomic`（5 分支） | **必须保证 fall-through 与默认分支语义一致**；`_detect_block` 顺序敏感（TOC/TASK/HR 先于列表）不可重排 |
| `collections.abc.Callable` | `views/line_view.py`、`views/toolbar.py` 的 `from typing import Callable` | `typing.Callable` 已弃用 |
| `ruff UP` 自动升级 | 全项目 `ruff check --fix` | 机械升级残留 `Optional[X]`→`X\|None` 等 |

**务实原则**：`itertools.batched`/`tomllib`/`asyncio.TaskGroup` 仅在有显式场景时用，不为用而用。

## 四方向性能优化清单

| 方向 | 现状（已实现） | 本方案优化（阶段） | 预期收益 |
|------|--------------|------------------|---------|
| 输入响应 | `reparse_line_atomic` 原子重解析、cursor_text_field key 含 li+nav_seq 保 IME、`_focus_cursor_field` use_effect 依赖移除 cursor_off、`_make_stable_cb`/`_cb_ref` 稳定回调 | 阶段3：纯函数提取后闭包重建不再重定义高频函数；阶段4：子组件提取后重渲染范围从整个 MarkdownEditor 缩到当前 LineView+cursor_overlay；阶段5a：控制器实例稳定→EditorActions 方法引用稳定→KeyDispatcher 不重绑 | 消除闭包重建临时函数对象与 `_cb_ref.current[key]` 查找开销；IME 组合态更稳 |
| 滚动流畅度 | `LineLayoutCache` 惰性构建、`_offset_prefix_ref` 前缀和 O(1)、`precomputed_vlayout` 共享测量(3→1)、非活动行零宽标记布局 | 阶段5a：`ScrollController` 收敛 `_offset_prefix_ref` 失效逻辑（统一失效信号减少漏失效漂移）；阶段5b（可选）：视口虚拟化只构建视口内行控件 | 10000 行滚动 FPS 提升（控件树 diff 是主瓶颈） |
| 启动速度 | 同步加载字体+同步解析 SAMPLE_MD、`parser.py` 模块级构造两个 mistune 实例 | 阶段2：`_md`/`_html_md` 改 `lru_cache` 惰性（`to_html` 延迟到导出）；阶段4：设置弹层/文件树扫描延迟到首次打开 | `import parser` 不再触发 mistune 插件链；首屏提前 |
| 大文件编辑 | `_offset_prefix_ref` 前缀和、`LineEditSnapshot` 行级撤销、`reparse_line_atomic` 单行重解析 | 阶段5a：控制器持有 ref 避免大文档闭包快照；阶段5b（可选）：增量解析仅重解析变更区间（围栏破坏回退全量）+ 视口虚拟化 | 10000 行打开延迟从 O(n) 降到 O(changed) |

**禁止改动**：`reparse_line_atomic`、`object.__setattr__` 静默更新、`line.notify()` 单次通知、`precomputed_vlayout` 共享、`_offset_prefix_ref` 前缀和、`LineEditSnapshot` 行级撤销——高频路径核心。

## 阶段依赖与提交节奏
