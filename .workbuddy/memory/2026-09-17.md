# 2026-09-17

## 代码块重写：去掉 flet-code-editor，改 Flet 原生双态实现

### 起因
用户要求"开启换行时，代码块内也自动换行"。排查发现 `flet-code-editor` 上游
`flutter_code_editor` 的 `CodeField.wrap` 是"已声明未实现"的空属性（对应 PR 仍是
Draft），Flet 侧也没暴露换行开关 → 产品上无法达成。用户拍板：**移除该依赖，用 Flet
原生重实现代码块**（Typora 式）。

### 落地方案
- 新增 `views/code_block.py`：双态组件
  - 浏览态 = 逐逻辑行 `ft.Text(spans=...)` + Pygments 语义色（`word_wrap` 控折行）
  - 编辑态 = 原生 `ft.TextField(multiline=True)`，选区/IME/撤销/软换行交给框架
- 新增 `services/code_highlight.py`：纯分词服务（惰性 Pygments + FIFO 缓存）
  **不变式**：`highlight_lines` 行数恒等于 `code.split("\n")`、逐行拼接恒等于原文
  —— 行号/逻辑行坐标/边界方向键跳出都依赖它。4 类异常统一回退纯文本。
- 新增 `utils/code_indent.py`：Tab/Shift+Tab 缩进纯函数
  `apply_indent(value, base, extent, direction) -> (value, base, extent)`
- 新增 `styles.Colors.code_syntax`：语义类别 → 主题色（亮/暗各一套）
- 契约零改动：`on_change/on_focus/on_blur/on_selection_change` 四件套语义不变，
  `views/editor/_fence.py` 与 `views/key_bindings.py` 未动

### 本次踩到的 flet 1.0 坑位（都已在真机上复现并验证修法）
1. **`ref` 是 `InitVar`**，只在构造时绑定。`field.ref = x` 事后赋值永不生效
   （`ref.current` 恒 None）→ 点击后收不到 FOCUS、要点两次才进编辑态。
   修：`ft.TextField(ref=my_ref, ...)`。也修了 `views/line_view.py` 公式编辑框的同款 bug。
2. **渲染后的控件被冻结**：`field.value = ...` / `field.selection = ...` / `field.update()`
   抛 `RuntimeError: Frozen controls cannot be updated.`。控件状态只能从渲染流入
   （写成构造参数）；只有方法调用（`await field.focus()`）例外。
3. **事件回调里 `e.control.value` 是渲染时文本**，客户端输入不回写。拿它配
   `e.selection` 的新偏移做变换 = "旧文本 + 新偏移"越界裁剪，真机实测**吃掉用户刚输入的字符**。
   修：文本以文档（`line.segments[0].text`）为唯一真相，回调只记偏移量。
4. **Tab 被 Flutter 焦点遍历消费，`KeyboardListener` 返回 `True` 也拦不住**
   （`KEYDOWN Tab` 与 `BLUR` 同帧）。flet 1.0 无 Focus/Shortcuts 控件、TextField 无
   `on_key_down`。修法：组件内嵌 `KeyboardListener` 包住编辑框 → 自行插入缩进
   → 标记 `tab_pending` 把随之而来的失焦当副作用（不退出编辑态）
   → `use_effect(..., [is_editing, tab_epoch])` 在重渲染提交后 `focus()` 收回焦点
   → `tab_pending` 由**收回后的 `on_focus`** 清除（在 effect 里清太早，拦不住那次 BLUR）。
5. **`KeyDownEvent` 只带 `key`、不带修饰键**（真机键名形如 `'Shift Left'`，
   后面还紧跟一个 `key=''` 事件要忽略）→ Shift/Ctrl 状态只能靠跟踪其自身 keydown/keyup。
6. 测试 harness：真实 flet 调度器是**先控件更新、再 effect**（`flet/session.py` ~707-717），
   harness 反了会让 `use_effect` 里 ref 指向旧控件；`Session.invoke_method` 无客户端时
   永久 await（`await control.focus()` 直接挂死），harness 必须打桩。
