# 2026-09-18

## 修复：代码块编辑态行宽异常 + 编辑时保留语法高亮

### 问题
代码块点进编辑态后每行可用宽度明显小于浏览态——真机实测编辑框文本区 **300px**，
浏览态代码列 **728px**（约一半），长行折行点大幅提前、块高多出 2 个视觉行
（`SIZE li=2` 从 219 → 259）；且编辑时语法高亮完全消失。

### 根因（用 `on_size_change` 打日志量测，不靠截图猜像素）
把两种结构并排渲染进同一固定宽度容器，一次启动就比出来了：

| 结构 | 文本区宽 | 说明 |
|---|---|---|
| `Row[gutter + Text(expand)]`（浏览态）| 728 | 基准 |
| `Row[KeyboardListener(expand)]`（旧编辑态）| **300** | 塌缩 |
| `Row[TextField(expand)]`（去掉监听器）| 760 | 正常 |

`ft.KeyboardListener(expand=True)` **只把自己撑开，传给 `content` 的是松约束** →
里面的多行 `TextField` 缩到内在宽度。次要因素：编辑框右侧 `content_padding` 多留了
一个 `Spacing.MD`；`letter_spacing` 未显式指定（`TextStyle` 默认 `None` 走继承，
两层可能取到不同字距 → 光标随字数线性漂移 0.25px/字形）。

### 改法
1. **叠层（编辑时高亮持续可见，Typora 式）**：把浏览态那个高亮正文层
   （抽出 `_read_column()`）作为编辑态**底层**，上面叠一个**文字透明**的
   `ft.TextField`——字符由高亮层呈现，编辑框只提供光标/选区/IME/撤销。
   两层显式同字体族/字号/行高/字距 → 宽度与折行点逐字对齐。
2. **宽度约束归位**：`KeyboardListener` 移到最外层包住整个正文；编辑框改由
   `Row([Container(expand=True, ...)])` 拿**紧宽度**，右侧 padding 归零。
3. `Stack` 必须用默认 `LOOSE`：滚动 `Column` 内交叉轴无界，`StackFit.EXPAND`
   会把高度算成 `inf`（探针实测，整块渲不出来）。
4. 关闭换行时两层放进**同一个横向滚动容器**，滚动天然同步。

### 真机验证
- 编辑态块高不再变化（`SIZE li=2 h=219.0` 仅出现一次，修复前进编辑态会变 259）
- 编辑态与浏览态折行点完全相同、行号与语法高亮均在、Tab/Shift+Tab 照常工作
- 光标经**逐帧差分**确认存在（`ImageChops.difference().getbbox()` 得到 5px 竖条，
  落点与插入缩进后的列位一致）——单张截图会抓到熄灭相位而误判

### 测试
`tests/test_code_block_native.py` 新增 5 项、改写 3 项（旧断言写死了"编辑态不应渲染
高亮层"与"监听器直接包编辑框"，随架构变更一并更新），全量 **1360 通过**。

### 沉淀
- 两条 flet 1.0 布局坑写进 `AGENT.md` 禁止的调用规则（KeyboardListener 不传紧宽度、
  滚动 Column 内禁用 `Stack(EXPAND)`）
- 探针技能补了「布局与叠层」小节 + `screenshot_burst()` 连拍助手：
  量布局用 `Container(on_size_change)` 打真实尺寸、验证闪烁元素用帧间差分

## 压缩：代码块头部行高 48 → 22

### 根因（逐控件量高，不是压内边距）
行高 = **最高子项**，与内边距无关。实测固有高度：`ft.Dropdown` **恒为 48**
（`dense=True` / `text_size=12` / `content_padding` 归零都不减，内部
`InputDecorator` 使然）、`ft.IconButton` **40**（`visual_density=COMPACT` 也只到 32）、
`ft.Text(size=11)` 才 17。所以"顶部行过高"的唯一成因是这两个 Material 控件。
给 `Dropdown` 设 `height=28` 能改外框，但**会裁切内部文字**（截图实测：文字下坠、
压到 24 时溢出到下一行标签上）→ 只能换控件。

### 改法
- 语言选择器 `ft.Dropdown` → 自绘触发器 `ft.PopupMenuButton`（22px，当前语言展示名 +
  小箭头；菜单 `UNDER` / 项高 28 / 勾选当前语言；选中走 `PopupMenuItem.on_click`）
- 折叠 / 复制 `ft.IconButton` → `Container(width/height=22, ink=True, tooltip=...)`
  （沿用 `views/status_bar.py` 既有紧凑按钮惯例）
- 头部 `Row(height=_HEADER_H)` 硬锁；移除装饰性 `DATA_OBJECT` 图标（语义与语言标签重复）
- 新增 `_HEADER_H = 22`、`_lang_display()`、`_lang_entries()`；
  `_lang_options()` / `ft.DropdownOption` 已删除

### 真机验证
- **A/B 法**：同一条渲染路径，把 `_HEADER_H` 提成模块全局，探针在同一页渲染两份、
  构建前临时改全局 → 块高 **260 vs 286（Δ=26px）**，与 48−22 严格相符；
  卡片边界像素法独立复现同一差值
- `PrintWindow` 高保真截图 + 2x 放大确认：标签/图标/行数在 22px 内垂直居中、无裁切

### 测试
`tests/test_code_block_native.py` 新增 12 项（行高锁定、头部禁用 Material 固有尺寸控件、
子项高度不超上限、图标按钮形态、行数标签、语言展示名、菜单项与勾选态、选中回传契约、
清单外语言追加、两个纯函数、折叠可用）；全量 **1372 通过**。

### 未完成的验证（如实记录）
语言菜单的**真实点击**未能验证：用户前台被一个疑似以管理员权限运行的行情软件占着，
低完整性进程的 `SendInput`/`mouse_event` 被 UIPI 静默丢弃（`SetCursorPos` 不受限，
故悬停 tooltip 有效、`GetForegroundWindow`/`WindowFromPoint` 校验也全过，但控件回调
不触发、截图逐帧全等）。该控件与回调写法是项目既有模式（`tool_area.py` 导出菜单等），
且有 12 项单测覆盖；真机交互待前台空闲时补验。

### 沉淀（探针技能）
- **截图一律用 `PrintWindow(PW_RENDERFULLCONTENT)`**：`ImageGrab` 抓的是屏幕区域，
  前台被占时会截到**别人的程序**且无任何报错（本轮真把行情软件界面当成了探针输出）
- `SetWindowPos` 必须显式声明 `argtypes` 且 `HWND_TOPMOST` 要写成 `c_void_p(-1)`：
  否则 `-1` 被当 32 位无符号数传出去 → `ERROR_INVALID_WINDOW_HANDLE(1400)` 且静默失败
- 抢前台用 `AttachThreadInput`（Alt 技巧与"最小化→还原"实测都抢不到）
- 窗口未激活时第一次点击只用于激活（标题栏亮、回调不触发）→ 同点连点两次
