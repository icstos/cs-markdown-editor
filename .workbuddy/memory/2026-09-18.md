# 2026-09-18

## 修复：代码块编辑态行宽异常 + 编辑时保留语法高亮

### 问题
代码块点进编辑态后每行可用宽度明显小于浏览态——真机实测编辑框文本区 **300px**，
浏览态代码列 **728px**（约一半），长行折行点大幅提前、块高多出 2 个视觉行
（`SIZE li=2` 从 219 → 259）；且编辑时语法高亮完全消失。

### 根因（用 `on_size_change` 打日志量测，不靠截图猜像素）
把两种结构并排渲染进同一固定宽度容器，一次启动就比出来了：

| 结构 | 文本区宽 | 说明 |
|---|---|---|
| `Row[gutter + Text(expand)]`（浏览态）| 728 | 基准 |
| `Row[KeyboardListener(expand)]`（旧编辑态）| **300** | 塌缩 |
| `Row[TextField(expand)]`（去掉监听器）| 760 | 正常 |

`ft.KeyboardListener(expand=True)` **只把自己撑开，传给 `content` 的是松约束** →
里面的多行 `TextField` 缩到内在宽度。次要因素：编辑框右侧 `content_padding` 多留了
一个 `Spacing.MD`；`letter_spacing` 未显式指定（`TextStyle` 默认 `None` 走继承，
两层可能取到不同字距 → 光标随字数线性漂移 0.25px/字形）。

### 改法
1. **叠层（编辑时高亮持续可见，Typora 式）**：把浏览态那个高亮正文层
   （抽出 `_read_column()`）作为编辑态**底层**，上面叠一个**文字透明**的
   `ft.TextField`——字符由高亮层呈现，编辑框只提供光标/选区/IME/撤销。
   两层显式同字体族/字号/行高/字距 → 宽度与折行点逐字对齐。
2. **宽度约束归位**：`KeyboardListener` 移到最外层包住整个正文；编辑框改由
   `Row([Container(expand=True, ...)])` 拿**紧宽度**，右侧 padding 归零。
3. `Stack` 必须用默认 `LOOSE`：滚动 `Column` 内交叉轴无界，`StackFit.EXPAND`
   会把高度算成 `inf`（探针实测，整块渲不出来）。
4. 关闭换行时两层放进**同一个横向滚动容器**，滚动天然同步。

### 真机验证
- 编辑态块高不再变化（`SIZE li=2 h=219.0` 仅出现一次，修复前进编辑态会变 259）
- 编辑态与浏览态折行点完全相同、行号与语法高亮均在、Tab/Shift+Tab 照常工作
- 光标经**逐帧差分**确认存在（`ImageChops.difference().getbbox()` 得到 5px 竖条，
  落点与插入缩进后的列位一致）——单张截图会抓到熄灭相位而误判

### 测试
`tests/test_code_block_native.py` 新增 5 项、改写 3 项（旧断言写死了"编辑态不应渲染
高亮层"与"监听器直接包编辑框"，随架构变更一并更新），全量 **1360 通过**。
