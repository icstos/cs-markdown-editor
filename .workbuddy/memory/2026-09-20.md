## 设置面板优化（用户 4 项诉求，已完成）

诉求原文：「1 右上角关闭按钮不随滚动条滚动；2 整体更和谐、美观、精致；
3 快捷键分类：相对于默认快捷键有修改的进行标记；3 增加关于：版本、联系邮箱、官方社群、用户手册」。

### 关键实现
- `views/settings_dialog.py` **整体重写**。右列结构固定为
  `Container(expand=True) > Column(expand=True)[固定头部, 1px 分隔线, Container(expand=True, 唯一滚动区)]`。
  头部（标题 / 说明 / 关闭按钮）在滚动区**之外** → 物理上不可能随内容滚动。
- **真机才发现的真 bug**：拆掉快捷键页内层滚动后，外层 `Column` 漏写 `expand=True`。
  父级 `Row` 的交叉轴约束是「至多 740」而非紧约束 → 外层列按内容取高 → 内层滚动列拿不到有界高度
  → 内容被卡片裁掉**且滚轮完全无效**。修复：外层列与内层滚动列都写 `expand=True`。
  教训：**嵌套滚动拆掉一层时，必须回头检查剩下的容器是否还能给出有界高度**。
- 新增统一行工厂：`_card` / `_badge` / `_switch_row` / `_slider_row` / `_dropdown_row` /
  `_value_row` / `_icon_button` / `_nav_item` / `_header`。标签列 `_LABEL_W=108`、数值列 `_VALUE_W=56` 定宽 → 各行左右边缘对齐。
- 撤掉全部 `ft.IconButton`（Material 固有高 40 压不下去），改用定尺寸 `Container(ink=True)`。
- 侧栏导航项改**整行可点**（`Container(ink=True, on_click=...)` 包 Row），改前只有文字那一点能点。
- 快捷键改动标记：`_shortcut_diff(current, default)` → `""` / `已清空` / `已自定义` / `已修改`；
  **比对前必须 `normalize`**（否则 `ctrl+comma` vs `ctrl+,` 误判为已修改）。角标 + 分类汇总
  「N 项已调整」+ 概览条「已调整 N 项 / 共 M 项」+ 「只看已修改」开关（面板内 `use_state`）。
  清空的项键位框显示**未绑定**，默认键写在说明行，避免「已清空」旁边写 `Ctrl+S` 自相矛盾。
- 新增「关于」页，替换原占位的「高级」tab。行工厂 `_about_row`，回调契约统一为
  `on_open(value)` / `on_copy_value(value)`（邮箱行在内部转 `mailto:`）。
- 新增 `config/app_meta.py`：应用名 / 标语 / 作者 / 许可 / 5 个外链常量 + `app_version()`
  （`importlib.metadata.version`，源码直跑回退 `_FALLBACK_VERSION="0.1.0"`）+ `runtime_summary()` + `mailto()`。
  `views/global_menu.py` 的 6 个硬编码 URL 改为引用它。

### 环境性坑（重要，下次别再误判成回归）
1. 宿主注入了**删除守卫**（`sitecustomize.py` 劫持 `Path.unlink`）：测试里自己 `unlink()` 清沙箱文件
   的用例会直接抛 `SystemExit: 1`（如 `tests/test_first_run_sample.py`）。栈里有 `[safe-delete]` 前缀即环境拦截。
2. 删除计数是**按工具调用累计**的 → 一次调用里连跑多轮回归，越往后越容易整体失败；以**最早那轮摘要**为准。
3. 本机 **PowerShell 工具的输出捕获不稳定**（原生命令输出赋给变量常为空）。
   跑批量回归要用 **Python 编排脚本**（subprocess + 正则取摘要），不要用 PS 循环。
4. OS 级输入注入（`SendInput` / `PostMessage` 滚轮）在本会话**时灵时不灵**：同参数一次滚到底、一次整批丢失。
   真机像素验证结论只取「确实注入成功」的那次运行。

## Git 版本管理模块（对标 VS Code 内置源代码管理，已完成）

诉求原文见 `TODO-Roadmap.md`「## TODO」下的代码块（五大项：更改管理 / 提交同步 / 历史记录 /
配套体验 / 技术约束）。

### 交付分层（新增 11 个文件 + 14 个文件改动）
- `services/git/`：`errors`（9 类异常 + 固定优先级归类 + 用户可读消息/建议）、`models`（状态/提交/
  分支/diff 模型）、`runner`（非交互 env、20s/180s 超时）、`porcelain`（`--porcelain=v2 -z` 解析、
  `\x1f`/`\x1e` 分隔的 log 格式）、`difftext`（统一 diff → hunks / 分栏行 / 二进制 / 冲突标记，
  `MAX_DIFF_LINES=12000`）、`repository`（`GitRepository` + 按根缓存的 `GitService`）。
- `app/_git_controller.py`：41 个 `git_*` 装配槽，**全部**用 `_schedule/_spawn/_run` 三件套调度；
  `_spawn` = 只读（不占 `git_busy`），`_run` = 写仓库（占忙碌态 + finally 释放）。
- `views/git_panel.py`（面板）、`git_diff.py`（覆盖式差异视图）、`git_branch_menu.py`（分支）、
  `git_widgets.py`（行工厂/按钮/过滤框）。

### 关键设计决定（值得复用）
1. **差异视图与分支面板做成覆盖层**（挂根 `Stack`，`visible`/`open_state` 控制），不做标签页——
   避免牵扯标签模型 / 脏状态 / 关闭确认 / 自动保存四条既有链路。
2. **提交框 `Ctrl+Enter` 用「具名焦点域」解决冲突**：新增 `native_scope.DOMAIN_GIT_COMMIT`
   + `KeyDispatcher._handle_git_commit_box`（在 `_handle_foreign_only` 开头消费，早于动作表），
   并**刻意不登记全局默认键位**——登记就会被并进 `_global_targets()`，在编辑器里抢走
   `Ctrl+Enter`（那里是 toggle_raw）。
3. **Escape 关闭覆盖层**放在 `handle()` 最前段（`_sync_modifier_keys` 之后、外来域门控之前）：
   覆盖层才是"前台"，且分支面板的「新建分支」输入框本身在外来域内，不走前置就会被原生
   输入框吞掉、面板关不掉。回调返回 False 时**继续走常规分发**（不能无条件消费 Escape）。
4. 自动刷新：App `use_effect` 依赖 `[workspace_folder, fs_version, 各标签脏标记元组]`——
   脏标记只翻转一次，所以不会每次击键触发 git 子进程；控制器内另有 0.12s 去抖。
   另：`open_panel()` 与活动栏 git 分支都触发一次刷新（保存文件不递增 `fs_version`）。

### 测试期发现的 3 个**真实缺陷**（都不是本次新引入的）
1. 「丢弃所有工作区更改」一个文件都没删：原实现 `unstage_and_delete(["."])`，
   `abspath(".")` 是目录、`isfile` 判定假。改为按状态条目**三分支**：
   已跟踪 → `discard_working`；未跟踪 → `delete_untracked`；已暂存的新增 → `unstage_and_delete`。
2. 「单文件历史」把仓库外文件当仓库内：`os.path.relpath` 对仓库外路径**不抛错**（返回 `..\..\x`），
   原 `try/except` 判边界全部漏判 → 改用 `GitRepository.contains()`。
3. 活动栏打开 Git 面板不刷新（只切面板），面板会停在旧快照。

### 测试方法（可复用）
