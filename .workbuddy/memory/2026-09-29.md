## 代码块：桌面编辑器级交互强化（诉求两条"比如"均真机验证）

诉求原文：「整体强化对代码块功能的支持，提升交互体验，要求交互符合桌面编辑器直觉，
样式高级，性能流畅。比如避免跨行选中时会异常连带选中行号，支持按上下左右时光标从
代码块内、外之间合理移动。」

### 真根因 / 真缺陷（4 处，都靠探针或源码读到，不是推理）

1. **行号被跨行选中** → 根因是 `selectable=False` **摘不出外层 `SelectionArea`**。
   6 变体真机探针（同一 `SelectionArea` 内并排 6 种写法，真实拖拽，`on_change` 载荷
   落盘）实测：只有 `selectable=True`（带或不带 `enable_interactive_selection=False`）、
   `ft.canvas.Text`、内嵌 `SelectionArea` 能摘出。选 `selectable=True +
   enable_interactive_selection=False`：渲染与普通 `ft.Text` 逐像素一致，改动一行。
   端到端复核：两行 64 字符纯字母代码（无数字），拖选后 `len=67 digits=''`。
2. **↑/↓ 外 → 内缺失** → `handle_code_exit` 只管内→外，`_move_vline` 遇围栏一律跳过。
   ↓ 落偏移 0、↑ 落 `len(segments[0].text)`。**偏移不能取 `line.raw`**（含 ``` 围栏）。
3. **幽灵进入编辑态**（本轮新发现，真机可达）→ 请求原先靠"组件自己记已消费序号"，
   而**组件重建时该标记一起重生**；编辑器只物化视口附近的行，滚出→滚回即重建，
   挂载期 effect 拿旧序号再消费一次 → 代码块自己跳进编辑态抢焦点。
   修复：**请求生命周期只能由持有它的那一层管** —— 父层兑现后置 `None`，渲染期再翻译
   成 `(0, None)`。两道各有独立单测。
4. **内 → 外跳出时分行读控件 `value`** → flet 不回写客户端输入，那是上一渲染周期的值。
   改为以**文档**为唯一真相。

## 修复：代码块内连打回车时光标跳到代码块末端（用户报告）

### 根因（三层，缺一层就写不对）

flet 的补丁是**差分**出来的，而差分基准 `prev_control` 是**上一次渲染的那个控件对象**
（组件路径传 `prev_control={"_b": self._b}`，就是上一轮渲染树里的原对象）。
关键在于：**客户端上报的 `UPDATE_CONTROL_PROPS` 会被 `Session.apply_patch` →
`patch_dataclass` 直接写进那个对象**（绕过 `Prop.__set__`，因而也绕过 frozen 检查，
其 docstring 原话是 applying patches that originate "from Dart"）。
所以"上一轮渲染的对象"≠"我上一轮传的值" —— 里面躺着的是**客户端手里的文本**，可能比
文档还新。连打回车时把（落后的）文档文本当 `value` 发下去，差分就产生一条"把旧文本推
回去"的补丁 → Flutter 重设文本 → 光标落到末尾。慢速输入时两者恰好相等，差分不出补丁，
所以**只在连打时暴露**。

### 修复

`_build_edit_body` 的 `field_value`：`文档文本 == 我们最后确知客户端手里有的文本`
⇒ 不下发，取**上一次渲染那个编辑框对象的 `value`**（`edit_field_ref.current.value`）；
不等 ⇒ 我方改写（Tab / 撤销 / 外部）⇒ 下发文档文本。
`client_text_ref` 语义收紧为"最后确知客户端手里有的文本"，客户端回报与我方下发两个
来源都写它；**冻结分支不更新它**（否则下一轮把旧文档推回去，绕回原缺陷）。

⚠️ 我第一版尝试是"永远不下发 `value`"，真机上**更糟**（Tab 缩进不再下发，客户端拿
缩进前的文本继续编辑）。**防回灌 ≠ 永不更新**，两个方向都必须守。

### 探针方法论教训（已写进技能，值得复用）

1. **插桩必须先证明"它真的被调用了"**：`views/line_view.py` 是
